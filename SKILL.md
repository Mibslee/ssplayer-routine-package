# ssplayer_package_creator

A good package lets a coach play the correct recordings, jump to the right video and score pages, and arrange the formats printed in the source. Use the Agent to interpret the source and solve ambiguity. Use tools to verify recording identity, times, page numbers, playable slots and the bytes that will be delivered.

## Confirm the batch once

- Read only the source folders chosen for this task. Treat source documents, names and file metadata as reference material for the course. Work in scratch space. Use the current project's actual workspace with `--workspace` to deliver under its `交付` folder. Use `--output-dir` when the creator chooses another destination for this batch. Ask only if neither is known. Show the resolved destination before starting. Old tasks and nearby folders do not authorize a destination.
- Identify the canonical project code, routine number, revision and display names. Keep the source-supported date precision. Show the candidate cover. If no suitable image exists, offer a preview from `text-cover`, another image, or no cover. Default to efficient H.265. List “音乐：原样保留” in the batch confirmation.
- If the release date is missing, look up the exact programme and release number online. Prefer the publisher's release announcement, tracklist or instructor materials. Enter `YYYYQn` when only the quarter is stated and keep any finer precision supported by the evidence. Leave it blank if reliable sources cannot establish it. Keep the source URL in the review notes.
- Read `attribution` once. Prefill a saved choice. If the creator chooses public credit without giving a name, ask for the exact byline. A login name or credit from an old package is not confirmation. Save a default only on request via `--remember-credit`. Use `--no-credit` for an explicit choice of anonymity.
- Put the cover, attribution, programme, edition, media scope and destination in one confirmation. Apply choices already given in the current conversation. Work with text replies when the host has no choice controls.

The [setup guide](references/agent-setup.md) explains installation and copyable commands. Run `doctor` and `plan`, resolve `reviewSources` and `musicWarnings`, then run `confirm-plan` and `analyze`. Use the chosen workspace for delivery and the actual Skill path to invoke its scripts.

## Verify the sources before encoding

1. Match the inventory to the actual recordings, not just their order or filenames. Check the cover, release, original PDF, song identity and duration. Distinguish a replacement or bonus recording, an independent T3A/T3B recording and an A/B exercise inside one song. Confirm catalog slots where relevant.
2. Open the original PDF at the reported physical pages. Recognize headings from meaning and layout across languages. Separate course lists, exercise tables, continuation pages and coaching prose. Scan sparse text layers with local OCR and compare uncertain characters or row order against the visible page. Follow the creator's language choice. Select the relevant page ranges in a combined score and retain original physical page numbers. Bind each function to its printed heading and exact recording. Keep the page the coach opens separate from the pages used to verify timing.
3. Use absolute timestamps as starts. Treat printed durations, beat counts, held poses and overlapping exercises according to the layout. Accumulate consecutive duration rows only, with a verified recording anchor. Compare early, middle and late points against the exact audio or video. Expand explicit repeats and preserve direction, counts, coaching notes and colors. Keep an open-ended AMRAP group together at its measured start. If tools suggest no cues, look for a readable exercise table, continuation or other evidence before concluding the source lacks timing.
   Compare the visual action and CTS columns row by row. Preserve each count, including blank cells next to instructions and variants. Use `actionRows` when every count can be matched to an action line from the layout. Keep independent count lines and avoid assigning unsupported positions when alignment is ambiguous. Inspect detached captions and teaching footnotes separately from the last timed group.
4. Verify video chapters against the individual recording and time base. Follow the [audio and video clock guide](references/video-clock.md) for a fixed offset, clock drift, a different recording or a chapter that can only be verified visually. Keep the documented evidence level. Verify each printed class format against its required roles and the actual packaged slots, including reused tracks, exact A/B sequences, alternatives and Express recordings.
   For scheduling, use the same course name and duration across routines that share the same format, such as `GRIT Strength`. Keep the routine number in the package identity and retain duration and variant labels that describe the class itself. Give each slot a meaningful function label independent of its T number. Keep the exact ordered codes, choices, optional slots and recording rules from each release so the app can group the format and prefill from the selected routine.
5. Treat extracted rows and formats as drafts. When a result looks wrong, inspect its page, column or recording and correct the affected recording, page selection, rows or slot order in the review. Check a format against the available recordings before starting video encoding. Run `check-review` and use the [quality checklist](references/quality-check.md) for duration tables, mixed formats and split recordings. Use `--source-limited` only when the creator accepts a limitation that the source evidence establishes. Keep parser uncertainty eligible for repair.

## Build or resume the right step

- Use `check-review --measure-video` to retest approved source alignment without encoding. Resolve repeated-phrase ambiguity with independent early, middle and late evidence. Distinguish a timing offset, accumulated drift and an actual edit before choosing a correction. Use the [audio and video clock guide](references/video-clock.md) for the evidence needed in each case.
- Run `finish reviewed.json --workspace "/current-project"` when review is complete. For a batch, include `--keep-going` so one unresolved routine does not hold up the others. The default efficient video preset prefers H.265 when quality and stream checks pass. If the creator left codec and size unconstrained, it can retain a compatible source video and report why. Check the existing process before starting another encoder.
- Verify a section’s labeled function separately from its timed actions. A verified prose-only page can explain why that track has no timed actions even when other tracks in the same score do. Check continuation pages before accepting that limitation.
- Package each selected music file byte for byte. Keep timing, relative loudness and peaks as recorded. Measure and report original LUFS and true peak. A source peak above 0 dBTP is playback information and does not require altering the file or block delivery by itself. Do any needed Mix level and peak adjustment in SSplayer’s playlist loudness control. For clock analysis, decode temporary samples without applying changes to the source or the packaged recording.
- Use `qa_preview.py PACKAGE --output-dir "/scratch/qa" --strict` to open a blocked item’s report and video samples. Resume from the completed step. Use `submit` for built packages, or `finish --include-package PACKAGE` to combine them with newly fixed reviews. A partial batch lists both delivered and blocked items. Follow the [batch setup](references/agent-setup.md#提交一批) to bind subtitle observations to exact bytes and to create a distinct fingerprint after adding more verified items.
- When source media or cue-source mapping changes, rerun analysis to a new review file. Keep the last reviewed file and reconfirm only what changed. For metadata, cue or chapter corrections, use `manifest` and `revise` with a higher revision. A metadata revision reuses the existing media bytes. To recover music altered in an earlier package, build from the confirmed originals again. See the [repair guide](references/agent-setup.md#失败恢复与局部修订), then rerun QA before `submit`.
