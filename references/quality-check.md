# 制作和质检

## 输入与命名

| 项目 | 核对方式 |
| --- | --- |
| 原始目录 | 使用本轮给出的路径。缺少时再询问。确认能读取，按路径核对音乐、视频、PDF 和封面。 |
| 输出目录 | 使用当前项目工作区的「交付」目录。用户本轮已选其他位置时按其选择。把完整路径放进批次确认。大文件在本地工作目录生成和验证。 |
| 项目和套路 | 用稳定的大写项目代码，例如 `BC`、`BJ`、`TONE`、`GRIT`。从 PDF、曲目清单和视频核对套路号，显示名例如 TONE 26。 |
| 发行时间 | 支持 `2024Q3`、`2024-07`、`2024-07-23` 或 `2024`。保留可靠来源支持的精度。文件日期和目录只是线索，无法证实时留空。 |
| 修订与署名 | 首次用 `1`。同一套路修改后提高修订号。使用贡献者同意公开的署名。 |
| 原谱体积 | 单份 PDF 上限 64 MiB。需要压缩时，核对小字、动作表列和物理页序仍可正常查看。 |

成品名称为 `项目_套路_版本.ssroutine`。项目或套路有不同叫法时，保留一个稳定代码。真实不同的课型或编排需要独立身份时，用经核对的套路代码区分。

例如「莱美核心」「Les Mills CORE」和「CORE」统一使用 `CORE`，第 63 套写 `63`。App 可以把这个代码关联到本机名为「莱美核心」的项目。多人维护未知项目时，先约定同一 ASCII 代码和套路编号，修订版沿用这两个字段。重复使用同一个编号的不同编排应由制作者明确区分。校验 App 预览中的导入位置和冲突的小节。

每首录音在自建项目中对应一个小节与版本。两份文件如果内容相同，先确认它们是否只是重复副本。同号的正曲、替换和独立 A/B 录音可以并存，制作时核对它们各自对应的声音、原谱和动作。

## 封面

查看计划里的 `coverCandidates`，检查每一种独立图片和内嵌封面，覆盖正曲、替换曲、加曲和短版。同一张图按摘要合并查看，同时保留受影响曲目。二维码、联系方式、卖家水印、导流文案、其他期号、无关图片和无法辨认的封面都需要更换。二维码提示之外，Agent 还要看图和理解文字，避免只有文字的广告漏检。原谱的页面和动作表留在原谱中。

优先使用用户提供的或原素材中已核实的同项目、同期官方套装图。发现任一首有广告时，用同一份已核实的干净封面更新该套路全部曲目、套路详情和质检首图。现有干净同版图经核实后可在批次确认中列出。没有可信的同版图时，联网先查课程发行方、教练资源和发行公告，核对项目、期号与来源后将候选一起展示，请用户一次确认。找不到时再请用户提供。用户也无可用图时，展示课程名和套路名的文字封面，等确认后使用或按用户选择留空。

用 `select-cover` 绑定已确认图的摘要。制作对各曲更新封面标签，核对当前音频包与更改前的音频包逐包哈希及时长，保留原文件。没有标准封面标签的裸 AAC 使用套路共享封面。工具会在交付质检复查成品封面是否一致及是否有大幅二维码。未解决的广告、错版、编码和关键内容问题须先修复。
## 替换曲、分段与波形图

1. 把实际音频与原谱的标题、项目号、发行批次、清单和时长交叉核对。带其他项目或期号的文件进入待确认区。保留不同声音的冲突候选，标出真实缺曲。
2. `T11` 加 `standard` 表示正曲，同号加 `alternative` 表示替换录音。用 `bonus` 标明已核实的独立加曲。普通歌名中出现 Bonus 之类的字样时，仍按原谱和课程位置确认。替换曲采用自己的音频哈希、视频证据和原谱页。
3. `T3A` 和 `T3B` 用于经确认的独立顺序录音。区分完整混音、拆段录音、其他课型、以及动作表里的 A/B 组合标记。动作组字母保留在动作栏，切开录音需有独立的分段和时间基准。BJ 原生目录存在重复候选时使用经核对的 `catalogTrackID`。
4. 「波形图」在这里是教练动作表。先从目录、栏目、标题和可见内容确认套路与版别，分清动作页、续页、技术讲解和替换页。 `pdfPage` 记录打开时的真实物理页，`pdfPages` 限定待提取的物理页。查看器页序可能与印刷页码不同。
5. 逐栏比对音乐提示、动作、CTS、REPS、教练注记和 LEVEL。检查跨行、重复图示、左右、箭头和同一时间点的多动作。肉眼看到但提取不出的重复图示可写成 `Repeat`。扫描页用 `--ocr` 后与可见原版核对。
6. 先判断数字是绝对时间还是持续时长。GRIT 常把区间时长印在动作表，邻近的技术讲解页可能完全没有时间。保留正确的 `pdfPage`，并按[分段时长表与曲内时钟](#分段时长表与曲内时钟)复核区间。不以 `pdfPages: []` 绕过可用的原谱。对确实没有动作时间证据的录音保留已核实的打开页和可用功能。原谱与 Masterclass 的差异可留在教练注记里。

## 小节功能与排课

1. 在同一轮原谱复核确认每条录音实际承担的功能。以有编号的动作表标题为依据，例如 T1 对应「01. WARM-UP」。技术讲解页可能沿用相同编号并标歌名。请打开对应动作表核实标题。
2. 正曲、替换曲、加曲和独立 A/B 录音分别核对。仅当原谱明确适用于该录音时才使用共享功能。独立录音需沿用各自的功能页。同号多个版别、标题冲突或只有动作内 A/B 时，先定位实际来源再填写。
3. 将原谱中的名称和从 1 开始的物理页码放入已核对录音的 `sectionFunction`，例如 `{"name":"WARM-UP","page":6,"approved":true}`。只有具备原谱证据的功能才可批准。功能可独立于时间线确认，未能核实时留空。
4. 质检第 3 栏回读成品的功能及来源页。原谱页上的小节号、明确版别或功能与填写值矛盾时，须更正才能提交。扫描页、未标版别或标题读不全时，标为「人工复核」。已看清原谱才填写。导入后用实际录音试排一份课单，核对功能与歌曲、小节归属一致。

一个 GRIT 套路含多个课型时，从命名课型表的 `sourceTrackReferences` 逐行核实课型、期号和原谱曲号。Strength T2 和 Cardio T2 可能是不同录音。核对实际包内编号后按原顺序另写一条含 `key`、`name`、`minutes`、`page`、`slots` 和 `approved` 的模板，分析建议留待复核。以印刷课型表的总时长为依据。单独的音乐目录可核实录音与顺序，只有明确时长来源时才填写课长。

## 把完整动作时间线写入包

对正曲、替换和独立 A/B 各自制作。逐页清点原谱中的起始动作、换侧、过渡和收尾。把完整动作和曲内时间写入 `review.json` 中对应录音的 `cues.rows`，每行记录关联的物理页、动作、拍数、次数、教练注记和已核实的原版颜色。

1. 先确认重复指令所引用的原段和目标段的起点、边界、拍数。对于节奏和拍数一致的重复，目标动作时间等于目标起点加上该动作相对原段起点的偏移。逐项核对节拍、速度变化和收尾，不明的时钟留待确认。
2. 把 `REPEAT BLOCK`、`REPEAT SEQUENCE`、重复图示及 A/B 组合引用展开为目标段实际的动作。按原谱限定的范围换侧，连同支撑手、持重手和准备动作核对。保留目标段的歌词、原谱物理页和恢复提示。同一时间点内有多个动作时，用换行保留次序和各动作的拍数。
3. 仅在确认分段第一行时填写 `block`。例如重复段从 4:15 开始，确认它属于第 4 段后，在 4:15 的第一行填 `block: 4`，后续动作行省略该字段。重复依据可保留在本地复核记录中，包内动作行直接写给教练看的动作。
4. 对照原谱复核每个重复段的首尾、有效拍数、次数和方向。逐个试听同素材的起始、中段、尾段，并比对原谱与视频所用时钟。确认当前录音所有可定位的动作都已核对，再设 `cues.approved` 为 `true`。原谱页或时钟无法确认时保留原谱入口，并把这条录音的时间线列为待核对。
5. 用成品重新生成第 6 张质检图和 HTML 报告。核对展开后的动作确实从包里读出、原谱落在对应页，报告中要能看见被抽查的分段、时间及拍数。

### 模型如何复核原谱

先从工具报告有疑义的小节、课型或时点入手。用原谱页图看列、编号和换页关系，再核对曲目清单与实际录音。时间表要结合音乐或视频确认。新布局可先写下各栏怎么读，让解释能应用到后续页。

    python scripts/ssroutine.py inspect-score "原谱.pdf" --pages 4,6-8 --output-dir "复核页"

`index.json` 记下原谱摘要、物理页序和文字来源。PNG 保留原页版面，TXT 记录各行、各词的位置。遇到扫描页或横向多栏时，以原页图核对文字。相邻页上没有重印表头时，先看编号、栏位和时间是否连续。页图只供本地复核。

| 从原始资料核实到的情况 | 要更新的内容 |
| --- | --- |
| 录音、曲号、版别或动作取页选错 | 更正计划，重跑受影响套路的分析并保留旧草稿。曲名相同的长短版分别核对。 |
| 确认了小节功能，但自动识别仍提示需复核 | 填写 `sectionFunctionReview`，记录与 `sectionFunction` 相同的物理页 `page`、可见标题 `observedHeading`、以及实际录音对应依据 `recordingBasis`。包和质检保留这条证据。 |
| 原谱动作、拍数、分组或跨页顺序看清了 | 校正 `cues.rows`，留原页位置和有依据的时点。遇到交叠、持续或循环动作可保留成组表达，拆分时需要确定各动作的时刻。 |
| 能核实片内计时或原谱课型，但候选漂移或漏行 | 核对对应时钟和完整课型表，更新实际章节或选曲槽。检查前、中、末时点以及每个必选槽能否填入实际录音。 |
| 原资料仍缺失或出现明确矛盾 | 写清受影响的录音、原页和证据。缺的决定确实会改变交付时再合并询问，其余项目继续。 |

例如，音乐清单列有正曲和同名短版，课型表又分行打印短课标题时，先读完整表头、选曲列和短版动作页，再试排。课时来自原谱，短版曲内时点来自该录音。独立的 45 分钟选项可以继续使用常规录音。等待工具判读时也可先标出哪些已通过底稿证据、哪些需要看原页。

### BODYATTACK 替换曲、Express 与课型

- 先对照音乐目录、动作页和实际音频。原谱同页明确点名替换曲并要求同编舞时可以共用动作页，再独立核对替换录音的拍点、时长和音乐段落。独立的 Express 剪辑用自己的动作表，或采用原谱明确指定的共用段落。没有拍点证据时保留待核状态。
- `Exp`、`Express` 或文件名前缀 `E5` 表示课型专用剪辑。以印刷课型表决定 `classEdition.minutes`，再从动作页和曲名核实版别。比如 30 分钟表里的 `Express 05` 要求该短版，而同一期 45 分钟表里的 `Track 05` 使用常规录音。
- 按版面逐列核对完整的课型标题、续行、栏目边界和每个小节。曲号可能印在 `Track` 下一行。斜线表示可选录音，只有原谱明确要求按顺序播放时才用 `consecutive`。遇到课型表使用 A/B 后缀而实际动作页或录音目录采用单号时，先核实该期的实际小节角色。
- 原谱动作栏里带时间和拍数的 `Sequences …` 属于有效重复指令。对照同页或续页的已定义动作展开，沿用这行的起点、拍数、次数及换边提示。原谱无法确定的动作顺序单独保留待核。
- 分别核实视频里是否出现每个录音。音轨有解说时，工具可在独立的低频和高频窗口复测同一时钟。找不到可靠章点时，先检查同曲短版、替换版和片尾加曲的实际内容及可见排布。

### BODYPUMP Block 与重复段

- 对齐原谱左栏编号、横向分隔线与下一条曲内时刻。编号在 Block 中间居中排版。校对首个 Block 是否有独立 INTRO，以及跨页或无编号的尾段。将可信边界写入首条动作的 `block`，每个 Block 只标一次。
- 按横纵坐标核对 MUSIC 内的乐句拍数、歌词、动作列和 REPS。保留半乐句、过渡、左右侧和未独立计时的恢复提示。若谱面时钟印成 `1.22`，先确认它位于分钟秒钟列，再用相邻录音时刻复核。
- `analyze` 可提出有分隔线、前置 Block、拍数和侧向依据的展开，审阅报告里的 `blockExpansion` 保留来源、拍数与展开时刻。核对组合重复的顺序和引导拍；只对指令指定的侧或站位做变换。对出现改编或不同速度的段落，按该版录音复测头中尾，修正时间线后再打包。
- 给已展开的单一来源 Block 写入 `repeatsBlock`。多源重复保留完整动作、目标 Block 和原谱页；把多个来源留在审阅证据。保留冲突条目待复核。按动作时间顺序抽查 App 的 Block 标题、展开动作、字幕/原谱跳转。
- 对独立的 45 分钟组合录音核对歌名、课型表标记和独立动作页。原谱标 `Track 05 (45)` 的模板应填写 `requiredDurationMinutes: 45`，并将组合录音标为 45 分钟版。普通 45 分钟版保持原印刷顺序。把原谱模板作为可调整的排课起点。


## 分段时长表与曲内时钟

先匹配「课型、期号、原谱曲号、曲名」，再定位动作表。相邻的技术讲解页适合读提示，带 `EXERCISE` 的分段页用于确认段落。自研课程的左右两栏可能是两种难度，也可能是同一个时点的教练提示。看清栏头、行线和阶段顺序，再决定动作如何对应时钟。读明白每个时间数字的含义，再决定是否能累加。拍数、并行动作、组内循环和整课时长不能直接相加。AMRAP 的起点可以定位时，组内动作作为这一个区间的文字保留。

GRIT 的分析结果会给出 `intervalReview` 候选。用同一录音或已经音画对齐的视频核实开头、中段、尾段的原谱计时。计时从音乐开始前已经走了 5 秒时，`intervalClock.anchorSeconds` 为 `-5`，开头当前动作从音乐的 0 秒可见。为 `intervalClock.observations` 写入各点实际的 `musicSecond` 与在画面或明确动作中核实的 `scoreSecond`。例如曲内 25 秒处的原谱计时为 30 秒。尾边界差几秒时检查是否为收操、切镜或版本差异。把核准的动作行写到 `cues.rows`，一并保留物理页与组内提示，再确认 `cues.approved`。验收会回读每行与原谱区间的对应关系。

## 验收及交付

- **声音和定位**　核对正曲、替换曲和各分段的身份。核验音频解码、实际时长与原音频数据，记录每首的 LUFS 和真峰值。高于 0 dBTP 作为原录音提示，音频照原样入包。混排后需要调整音量或峰值时，在 App 的「歌单响度一致化」处理。按[音画校时指南](video-clock.md)核对前、中、后段，再区分已同步、按画面跳章和仍待核验的结果。
- **原谱与外观**　核对原谱确实能打开和落在正确页，动作行有原件证据；确认发布日期精度、封面与项目归属。
- **App 与排课**　Pro 导入后检查分节、替换与独立 A/B 段。用已导入的真实曲目在对应项目排列、保存并调用课单，检查顺序。再次导入和重开后应保留已有编辑和人工关联。若同一录音已经被教练放在别的小节，查看导入回执的冲突位置。有两个本机项目都匹配时，在导入前确认一个目标。
- **交付**　用 `verify` 重新核验载荷。交付文件名、SHA-256、音乐数、可用视频章、符合证据的原谱页和动作数，以及缺项。说明验收是在制作工具、媒体解码、模拟器还是实际安装中完成。送达目标目录后再读回摘要并核对。

没有 Pro 的制作者可以一并交付[九宫格与可视报告](agent-setup.md#生成九宫格质检图)。先查看左上首图的套路、封面、实际包体积和媒体参数。可提供署名与已核实的制作时间。对位图用包内媒体复测，可在报告展开每首的测量值和动作。App 内课单验证单独记录。

视频、原谱和时间线的可用程度取决于原始资料。可制作仅有音乐的课程，但需要制作者明确确认范围。存在来源证据时补齐。定位或时间轴不符时，先保留本地草稿和可读原谱，解决冲突后再生成投稿指纹。

正式交付前执行 `check-review`。报告区分待补证据和已核实的素材限制。完整通过或带有已核实的素材限制时可以生成指纹。确实没有视频或原谱时，在制作者一次确认范围后使用 `--source-limited`。已有原谱里的动作表、视频教学片段、小节身份及选曲要求继续核验。收尾曲经原谱音乐清单证实属于附加内容时，可保留音乐和原谱入口。重复剪辑的片尾没有独立可靠时钟时，移除误导性的跳转。

核对首图的字幕结论与抽样方法。独立轨、闭路字幕和画面字幕各自核对，片头标题、计时器、课程标签和水印不记为画面字幕。缺少文字识别引擎或判读有歧义时应实际查看采样图。

缺少发行日期可按已核实内容继续制作。没有独立音乐的章节可以在原视频或原谱中查阅。课单选曲使用实际录音。

同一视频容器有多条画面轨时，先对照早、中、尾实帧，识别干净主画面、带水印版、硬字幕版或其他机位。确认唯一默认轨符合交付范围后再编码。检查标题、节内计时和时间戳。音轨、独立字幕和官方章节要验证保留。
